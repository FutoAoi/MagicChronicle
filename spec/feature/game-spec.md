# MagicChronicle ゲーム仕様書 初版

- 文書版: 0.1.0
- 基準日: 2026-07-15
- 状態: 公開資料から再構成した初版。`question`項目は実装判断に使用しない。

## 1. 用語

| 用語 | 定義 | 状態 |
|---|---|---|
| 魔法陣 | 盤面へ配置するカード由来の装置。魔法弾が接触すると効果を発動する | `source` |
| 魔法弾 | 盤面を移動し、魔法陣の効果を受け、対象へ作用する実行単位 | `analysis` |
| 耐久 | 魔法陣が発動可能な残り回数に相当する値。発動時に減少し、0で消滅する | `source` |
| 霊陣 | 通過時ではなく破壊時に効果が発動する魔法陣 | `source` |
| コスト | 1配置ターンに魔法陣を置くための制約値 | `source`。回復周期は未定 |
| バフスタック | 効果量または継続回数を表す値 | `source`。効果ごとの意味が不統一 |
| ラン | 拠点から出撃し、分岐マップを進み、終了して拠点へ戻る一連のプレイ | `analysis` |

## 2. シーンと画面遷移

公開仕様の遷移図には、タイトル、拠点、チュートリアル、ステージセレクト、インゲーム、イベント、エンドシーンに加え、オプション、クレジット、図鑑、ショップ、デッキ、山札等のパネルがある。

### 2.1 タイトル

- 画面クリックまたはタップで拠点へ移る。
- 右上にオプションとクレジットを置き、対応パネルを開く。

### 2.2 拠点

- 古代遺跡が点在する背景を用いる。
- タイトル、図鑑、ショップ、出撃準備へ移動できる。
- 図鑑はカードとキャラクター／敵の一覧を表示する。
- ショップはキャラクター解放とカード解放ガチャを扱う案がある。
- 出撃準備からキャラクター選択、チュートリアル、ステージセレクトへ進む。

### 2.3 ステージセレクト

- 分岐マップで接続済みの次ルームを選ぶ。
- ルーム種別はノーマル、エリート、ボス、イベント、ショップ、鍛冶。
- ショップは回復・カード購入、鍛冶はカード強化を提供する案がある。
- 現在地にキャラクターアイコンを表示する。
- オプションと魔法陣デッキ確認パネルを開ける。

### 2.4 インゲーム

公開仕様にはドロー、配置、攻撃、報酬、カード周りの見出しだけがあり、詳細はゲームシステム資料と実装観測から補う。

### 2.5 イベント／チュートリアル／エンドロール

画面別仕様は未記載である。イベント題材の候補だけが存在するため、選択肢、コスト、結果、再訪、ラン状態への反映を決める必要がある。

## 3. 戦闘盤面

- 中央に5x5の配置マスを持つ。
- プレイヤーは手札から魔法陣をドラッグして配置する。
- 配置はコスト制であり、無制限には置けない。
- プレイヤーの魔法弾は盤面左側から直進を開始する。
- 魔法弾が魔法陣へ触れた瞬間に、その魔法陣の効果を適用する。
- 効果は方向転換、分裂、ダメージ、状態異常、ドロー、回復、通貨、耐久操作等を含む。
- 魔法陣は発動ごとに耐久を消費し、0になった時点で消える。
- 破壊後、その位置は後続の魔法弾へ影響しない。
- プレイヤー攻撃後に敵が攻撃し、敵の魔法弾でも同じ魔法陣が発動する。

## 4. ターン進行

現資料から確定できる最小フローは次のとおり。

1. ターン開始・ドロー。
2. 魔法陣の配置。
3. 配置終了を確定。
4. プレイヤーの魔法弾を解決。
5. 敵の魔法弾を解決。
6. ターン終了効果と継続状態を更新。
7. 勝敗未決なら次ターンへ進む。
8. 勝利なら報酬を選び、ステージセレクトへ戻る。

`question`: 複数弾の同時性、分裂弾の順序、同一魔法陣への同フレーム接触、霊陣と耐久0の処理順、敵が複数いる時の行動順は未定義である。

## 5. カードとデッキ

- カードは魔法陣の配置に用いる。
- ステージクリア報酬で新しいカードを獲得し、ラン内デッキを構築する。
- カードにはコスト、効果、耐久、方向や分裂等のパラメータがある。
- 報酬は複数候補から選ぶ画面案がある。
- 鍛冶でカードを強化する案がある。

### 未決定のデッキ契約

- 初期手札、毎ターンドロー数、手札上限。
- 山札切れ時の再構築と、捨て札・消滅札の区別。
- 配置済みカードがいつどこへ移るか。
- 報酬スキップの価値、カード削除、レアリティ、強化上限。
- ラン終了時のデッキ初期化と恒久アンロックの関係。

`code`: 既存AI Formatレビューは、消耗済みカードの再投入と空山札参照をHighとして報告している。仕様決定と回帰テストを同時に行う必要がある。

## 6. 魔法陣効果カテゴリ

| カテゴリ | 例 | 設計上の役割 |
|---|---|---|
| 経路 | 上下左右、分割2〜4方向、スキップ、加速 | 経路構築 |
| 攻撃 | 単体、範囲、全体、高火力、移動距離参照 | 勝利手段 |
| 維持 | 耐久回復、周囲耐久変更、破壊 | 連鎖寿命の管理 |
| 資源 | ドロー、コスト、通貨、回復 | 行動・経済 |
| 状態 | 筋力、疲労、弱体、毒、再生、カウンター | ビルド差別化 |
| 霊陣 | 破壊時攻撃、回復、バフ、通貨等 | 破壊順パズル |

## 7. バフ・デバフ

### 7.1 効果候補

- 筋力: 魔法の攻撃力を上げる。
- 疲労: 魔法の攻撃力を50%下げる。
- 弱体: 被ダメージを50%増やす。
- 毒: ターン終了時にスタック分のダメージを与える。
- 再生: ターン終了時に回復する。
- カウンター／反射: 受けた攻撃の一部を返す案、または弾を跳ね返す案が併存する。
- コスト増減: 使用可能コスト最大値を変える。
- 追加カード: ターン開始時ドロー数を増やす。
- 連続: 魔法弾の発射回数を増やす。
- コンボ: 移動マスごとに攻撃力を増やす。
- バーサーカー: 自傷をトリガーに筋力または怒りを得る。
- テクニカル: カード効果の再発動案と、毒弾付与案が併存する。

### 7.2 仕様矛盾

1. 消費型バフの回数減少が「カードドロー時」「敵攻撃直後」「毎ターン」「特定トリガー」と資料ごとに異なる。
2. 筋力は `+1`、`スタック分加算`、`倍率`の読み方が混在する。
3. カウンターはダメージ割合返却、反射は弾反転として分離すべきか不明である。
4. テクニカルは効果再発動と毒付与で別能力として記述されている。
5. コストマイナスはプレイヤーへのデバフか、カードコスト軽減か名称から誤読しやすい。

承認されるまで、これらを実装の正本として扱わない。

## 8. 敵と勝敗

- 敵は通常攻撃、自己バフ、盤面干渉を行う。
- ノーマル敵は弱い魔法陣を盤面へ置く案がある。
- ボスは落石による上書き・通行不能、反射、大型当たり判定等の固有ルールを持つ案がある。
- 通常戦、エリート戦、ボス戦を区別する。

### 未決定

- プレイヤーHPが0になった際のラン終了、復帰、報酬保持。
- 敵全滅以外の勝利条件、ターン制限、引き分け。
- 敵の意図表示とターゲット規則。
- 大型敵の複数マス当たり判定と分裂弾の命中回数。

## 9. ランと内部経済

### 9.1 想定ソース

- 戦闘報酬のカード。
- 魔法陣効果またはイベントからの所持金。
- ショップ・イベント・報酬からの回復、バフ、強化。

### 9.2 想定シンク

- ショップのカード購入と回復。
- 鍛冶のカード強化。
- 拠点ショップの解放／ガチャ。

### 9.3 未決定

- 通貨の種類、初期値、戦闘ごとの期待獲得量、価格曲線。
- ラン内通貨と恒久通貨の分離。
- カード獲得が常に強化になることによるデッキ肥大への対策。
- 回復と強化の機会費用、難易度別の資源供給。
- ガチャと有料課金の有無、確率表示、救済、重複処理。

## 10. 世界・物語

- 塔は古代文明の魔法陣研究施設である。
- クロニクルは魔法陣を平和利用しようとし、カイロスは兵器利用を望んだ。
- クロニクルはカイロスを封印し、塔へ守護者を配置した。
- プレイヤーは事情を知らずクロニクルを倒し、結果としてカイロスを復活させる。
- カイロスが裏ボスとなる。

`question`: プレイヤーの選択可能性、周回での真相開示、エンディング分岐は未定義である。

## 11. 入力・表示・アクセシビリティ

- PCではクリックとドラッグ、モバイルではタップとドラッグを前提とする。
- 方向、敵経路、発動順、耐久、コスト、対象、ダメージ予測を視覚的に区別する必要がある。
- 色だけで魔法陣や敵味方を区別しない。
- モバイルsafe area、最小タップ領域、文字サイズ、横持ち／縦持ちは未決定。
- キーボード・ゲームパッド操作、入力再割当、振動、演出軽減、速度変更は未決定。
- ローカライズ対象言語と文字列管理方式は未決定。

## 12. データと保存

- カード、バフ、敵、ステージ、イベントはデータ駆動のUnityアセットとして実装観測されている。
- ID重複、欠損参照、無効なイベントID、カード効果と説明文の不一致をビルド前に検証する必要がある。
- ラン状態、恒久解放、設定、図鑑の保存単位・バージョン・破損復旧は未定義である。
- タイトルから新規ランを開始した時のデッキ、所持金、HP、マップ、バフの初期化契約を明文化する。

## 13. 初版の受け入れ条件

次版へ進む前に、少なくとも以下を決定する。

1. ターン内の完全な処理順と同時接触規則。
2. 山札・手札・捨て札・消滅札・配置済みカードの状態遷移。
3. バフごとの効果式、減少トリガー、上限、表示。
4. ラン開始／勝利／敗北／中断／新規開始の初期化と保持。
5. 通貨ソース・シンクと拠点ガチャの位置づけ。
6. チュートリアル、イベント、エンドロールの最小仕様。
7. PC・iOS・Androidの優先順位と入力・UI・性能のrelease gate。
8. コアループの自動テスト対象と、TGS試遊の成功指標。
