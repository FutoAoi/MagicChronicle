学生・初学者向け

このゲームは「盤面へカードを置く」「弾の通り道を考える」「次のカードを選ぶ」「分岐したマップを進む」という複数の遊びを重ねている。珍しさは各部品ではなく、自分と敵が同じ魔法陣を使い、魔法陣が途中で壊れるため、攻撃の道が時間とともに変わる組み合わせにある。

新規性

新規性は7.6/10。新規性を上げるための追加機能は不要である。現在の組合せは説明可能な上限へ近く、さらにシステムを足すと予測不能性が増す。改善判断はholdとし、共有盤面・耐久崩壊・敵利用の三点を一つの短いプレイで証明する。

ループ

  1. 戦闘内: 手札確認 → 配置 → 自弾解決 → 盤面変化 → 敵弾解決 → 次の判断
  2. ラン内: 部屋選択 → 戦闘/イベント → 報酬 → ビルド更新 → 次のリスク
  3. 複数ラン: 発見 → 図鑑/解放 → 別構成の探索

戦闘内ループはコードで確認できる。ラン内ループはマップ・報酬・ショップの骨格がある。複数ランの持越し規則は情報も実装も不足している。

遊びの辞書からUXへつなぐ実装

1. 解決予告タイムライン

  • 辞書: system:board-card:rule-resolution、system:puzzle:s06
  • 実装: 配置候補から自弾・敵弾・発火・破壊を同じイベント列で予測し、番号表示する
  • UX接続: 操作→規則→結果の因果を予測でき、複雑さを戦略へ変える
  • 優先度: 最高

2. 失敗の因果リプレイ

  • 辞書: system:puzzle:s07、挑戦と回復
  • 実装: 最後の攻撃列を短く再生し、被害へ至った魔法陣を強調する
  • UX接続: 失敗を次の仮説へ変え、再挑戦の納得感を上げる
  • 優先度: 高

3. ビルドタグと変種検査

  • 辞書: system:deckbuilder:s02、system:roguelike:s08
  • 実装: カードへ経路・耐久・破壊時・状態のタグを持たせ、報酬候補の偏りを自動検査する
  • UX接続: 報酬選択時に「何が強くなるか」を一文で示せる
  • 優先度: 中

配信映えへの接続

予告とリプレイはプレイヤーだけでなく視聴者の理解も助ける。連鎖数だけを大きく表示するより、「3番の破壊で進路が変わり、5番が敵へ到達」のように上手さの因果が読める方が切り抜き価値を作る。

不足情報

  • 辞書対応を実プレイで裏付ける操作記録
  • 山札・捨て札・除外、同時発火、死亡、seed、持越しの正式規則
  • 既存類似作品との構造比較とプレイヤー認知

不足実装

  • 解決キュー、予告タイムライン、因果リプレイ
  • カードタグ、報酬分布検査、seed付きラン再現
  • 連鎖理解率と失敗後説明率の計測
